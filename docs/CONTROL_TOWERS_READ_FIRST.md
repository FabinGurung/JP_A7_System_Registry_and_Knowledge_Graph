# A7 CONTROL TOWERS — READ FIRST

**Purpose:** Explain what a control tower is and route to the true owner of controls, source, templates, and artifacts. This is not permission to import confidential Drive data into public GitHub.

## Vocabulary

- **Global control plane (A7):** permanent semantic identities, rule owner registry, provider/fact authority, typed relationships, conflict precedence, cross-module routing and public-safe policy discovery.
- **Module control tower (e.g. R&D):** executable governance for a single specialist domain. R&D already has machine contracts for repository, discussion, LaTeX, presentation, and website workflows. Contracts alone do not prove institutional typography/layout constraints have been fully admitted.
- **Private normative control tower (A9 Drive):** authoritative read-first policies, organization/approved university templates, code-first PDF-first presentation v2.2, thesis control v1.23, AI tool routing v0.42, source admission, release QA and preservation rules. Must be resolved live by an authorized account.
- **Main/Local libraries:** A9 original stable artifact identity, links, address lookup, version/run logs, local journals, save router, PRE/POST, ACK/consumption, and audit history. Not automatically replaced by Git history.
- **Execution and product sources:** code, TeX, generators, templates, job scripts and CI in the owning repo; private originals/approved documents and generated PDF/PPTX in Google Drive; never reverse authority from a rendering.
- **AI:** applies a retrieved control for a bounded request, performs provider operations, reports readback/debt, never invents a current rule.

## Work handover between ChatGPT accounts

A Work task can be conducted in either account if the account has Work and each connector is authorized. A second ChatGPT login has independent plugins, provider permissions and chat history; a shared public Git repository does not grant mutation permission. Prefer the **same GitHub provider login**, connected separately to the account, rather than inviting another GitHub identity as collaborator. When using a second GitHub identity, grant only necessary repository collaborator access; Drive access to private materials requires a separately authorized Drive account or explicit least-privilege sharing. Do not share credentials or secrets in prompts. Do not fork public authoritative controls into an untracked competing authority.
